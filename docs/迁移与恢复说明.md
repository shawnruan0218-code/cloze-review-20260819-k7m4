## 本地数据兼容

首次打开新版网站时，程序读取原有 `cloze-review-library-v1` 和
`cloze-review-annotations-v1`，复制到独立 IndexedDB
`cloze-review-20260819-k7m4-idb`。原键不会清空或改名。

登录 GitHub 后，客户端先上传 dirty queue，再按单调递增 cursor 分页拉取，
最后按 `updatedAt -> payloadVersion -> clientId/payload` 的确定性顺序合并。
退出只清除本项目会话，不删除复习数据。

## 数据恢复

1. 从 Actions Artifact 或私有备份仓库下载 `.sql.gz.enc`。
2. 在终端设置 `BACKUP_ENCRYPTION_KEY`。
3. 运行 `scripts/restore-d1-backup.sh <文件>`，先完成解密和内容校验。
4. 先恢复到测试 D1，核对记录数和 `PRAGMA quick_check`。
5. 另做一份当前正式 D1 导出后，才向正式 D1 执行恢复。

恢复脚本默认只验证，不会自动写入正式数据库。

## 请求量预算

- 空闲兜底：每台可见且已登录设备最多约 288 次/天。
- 两台设备纯空闲：约 576 次/天。
- 三个标签页：Web Locks 只允许一个后台同步主标签，仍约 288 次/设备/天。
- 普通修改：连续操作合并为一次 push 和一次 pull，约 2 次请求/操作批次。
- 首次 2,797 个实体：约 28 个 push 批次，加最多 6 个 pull 页面和会话请求。

正常两台设备预计远低于每日 3,000 次 Worker 请求；Cloudflare 免费账号下的
多个 Worker 仍共享每日 100,000 次额度。
